# 3.3 内存注册、DMA 与地址转换

第二篇把 MR 看成地址范围和权限。现在继续解释：应用只有一段连续虚拟地址，网卡怎样找到实际存放数据的页面？为什么一块大缓冲区注册起来可能需要明显的时间？

先考虑普通主机内存的传统注册方式。它需要保持页面可用于设备访问，建立 DMA 映射，并创建设备能够检查的地址与权限描述。

## CPU 地址与设备地址

`malloc` 返回进程虚拟地址。虚拟地址连续，并不要求背后的物理页连续。CPU 通过页表找到这些页，设备则需要自己的访问映射。

```text
CPU：进程虚拟地址 → CPU 页表 → 物理页

RDMA：请求地址 + key → 设备内存描述 → DMA 地址
                                      ↓
                              IOMMU（若启用转换）
                                      ↓
                                    物理页
```

在常规 MR 中，请求继续使用应用约定的地址，设备利用注册时建立的描述定位页面。应用不应该把 CPU 指针强行解释成物理地址，也不应绕过 DMA API 自行推测设备地址。

启用 IOMMU 时，DMA 地址还可经过 IOMMU 转换。是否采用转换、直通或其他映射方式取决于平台配置，不能用同一个地址图推断所有机器上的实际开销。

## 注册时建立哪些东西

传统注册会固定所需用户页，使设备访问期间这些页不被普通内存管理随意收回；内核准备 DMA 映射，驱动再建立设备侧的内存对象。以 mlx5 为例，MKey 保存相应转换与权限信息，应用看到的是 `lkey` 和 `rkey`。

注册范围覆盖更多页面时，页面处理和转换表维护可能增加。多张 NIC 分别使用同一缓冲区，也可能需要建立各自的设备资源。因此，注册时间不仅与字节数有关，还与页面组织、设备数量、并发方式和驱动有关。

注册本身不把 CPU 虚拟地址变成一块固定物理连续内存。页对齐只是让范围管理清楚；使用大页还需要实际分配到大页，并由对应路径支持。

## 地址转换也有工作集

IOMMU 和设备会缓存转换信息。访问跨度、页面数量和缓存命中情况可能影响 DMA 成本。较大的映射粒度有时可以减少表项，但是否有效要结合实际页大小、映射方式和硬件能力验证。

ATS（Address Translation Services）是 PCIe 设备参与地址转换的一类能力。它需要平台与设备共同支持，属于进一步分析转换瓶颈时阅读的内容。不能把“关闭 IOMMU”当作通用调优步骤，它还承担隔离和虚拟化职责。

## ODP 把部分准备推迟到访问时

ODP（On-Demand Paging）允许特定注册方式按需处理页面。地址范围可以先登记，设备访问尚未准备的页面时，由支持的驱动和内核补齐映射。

它改变了成本发生的位置：初始化可能更轻，首次访问则可能出现额外延迟。因而比较时应把第一轮与重复访问分开。ODP 也不是 GPU 显存注册的另一个名字，二者使用的内存管理与映射路径不同。

初学实验保持普通 MR 即可；需要很大或稀疏地址空间时，再查询设备 ODP 能力和应用延迟要求。

## 从机制理解注册复用 {#registration-cost}

如果每条小消息都重新分配、注册、传输、注销，页面和设备资源管理可能比真正的数据搬运更昂贵。内存池把一块较大区域先注册，再用不同地址偏移服务请求，就能摊薄初始化成本。

另一种做法是缓存已注册区域。缓存命中必须同时满足设备、地址范围、权限和底层分配仍有效。地址 `p` 释放后，新对象恰好又位于 `p`，并不意味着旧缓存条目可以继续使用。

```text
分配与注册 → 多次借出子区域 → 等待所有访问结束 → 注销 → 释放
```

这条寿命链既解释性能收益，也解释缓存为何容易出错。省掉重复注册的同时，应用需要知道每条在途请求和每个远端授权仍引用哪块内存。

可用相同大小的缓冲区比较“一次注册后重复传输”与“每次注册再传输”。分别记录注册、搬运、注销的时间；不要只报告一个合计带宽，否则无法知道变化来自哪一步。第四篇给出统一测量方法。
