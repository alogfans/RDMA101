# 2.3 Memory Region

设备和保护域准备好以后，程序需要给网卡一块可访问的内存。`malloc` 返回的指针可以供 CPU 使用，但网卡还需要知道这段地址对应什么页面，以及允许怎样访问。内存注册把这些信息交给设备，成功后返回 Memory Region，简称 MR。

本章先讨论普通主机内存和传统注册方式。GPU 显存、按需分页等机制在后文使用同一个地址、权限和生命周期模型继续展开。

## 注册一段内存

下面的片段假设 `pd` 已创建，注册一块 4096 字节的缓冲区，允许远端写入：

```c
size_t size = 4096;
void *buffer = malloc(size);
if (!buffer) return -1;
struct ibv_mr *mr = ibv_reg_mr(pd, buffer, size,
    IBV_ACCESS_LOCAL_WRITE | IBV_ACCESS_REMOTE_WRITE);
if (!mr) {
    perror("ibv_reg_mr");
    free(buffer);
    return -1;
}
```

注册没有把这块内存复制到网卡中。应用仍使用原来的 `buffer`；驱动与设备准备地址映射和保护信息，使后续请求能引用它。常规注册还涉及固定页面，因此受系统锁定内存限制及设备资源约束。

`ibv_reg_mr` 的普通主机内存接口不要求起始地址必须页对齐。示例使用页对齐缓冲区，是为了让地址范围易于观察和管理。页对齐也不等于使用大页。

## 权限如何对应数据方向

MR 的权限描述设备访问，不能直接按 CPU 的 `const` 或可写指针理解。只作为 SEND 或 WRITE 数据源时，本地设备读取权限是隐式提供的；接收数据、接收 READ 结果等场景则需要设备写权限。

| 缓冲区用途 | 所需 MR 标志 |
|---|---|
| 本地 SEND / WRITE 源 | 可用 `access = 0` 注册 |
| RECV、READ 或 Atomic 的本地结果 | `IBV_ACCESS_LOCAL_WRITE` |
| 接受远端 WRITE | `IBV_ACCESS_LOCAL_WRITE | IBV_ACCESS_REMOTE_WRITE` |
| 允许远端 READ | `IBV_ACCESS_REMOTE_READ` |
| 接受远端 Atomic | `IBV_ACCESS_LOCAL_WRITE | IBV_ACCESS_REMOTE_ATOMIC` |

设置远端写或原子权限时，同时设置本地写权限是 API 要求。远端操作还必须满足 QP 的访问设置；MR 与 QP 任一层不允许，操作都不能成功。

CPU 是否可以写入这块内存，由进程内存映射决定。MR 标志没有替代进程页表权限，也没有阻止 CPU 在传输期间错误地修改缓冲区。保持数据稳定仍是应用的责任。

## lkey 和 rkey 用在不同位置

成功注册后，`mr->addr` 和 `mr->length` 描述范围，`mr->lkey` 用于本地请求的 SGE，`mr->rkey` 交给需要访问这块内存的远端。

以 A 写 B 为例，A 的请求组合了两端的信息：

```text
本地源：A.buffer + 长度 + A.mr.lkey
远端目标：B.buffer 的地址 + B.mr.rkey
```

两个 key 都需要与所描述的地址匹配。把 B 的 `rkey` 放进 A 的本地 SGE，或只交换地址而不交换权限凭证，都不能构成正确的访问。

请求可以访问 MR 内的一个子区间，不必每次使用整个 MR。假设注册范围为 `[p, p + 4096)`，从 `p + 1024` 传输 512 字节仍在范围内；从 `p + 4000` 传输 512 字节则越界。检查时应验证完整区间，并在计算末地址时考虑整数溢出。

## 从传输到注销 {#mr-lifetime}

普通非 inline 请求提交后，网卡仍可能访问底层内存。因此传输期间不仅要保留 MR，也要保留缓冲区的分配。应用等到相关请求安全结束后，才能注销并释放：

```c
/* 前提：没有新的本地或远端访问，既有访问已经结束。 */
if (ibv_dereg_mr(mr) != 0) {
    perror("ibv_dereg_mr");
    return -1;
}
free(buffer);
```

如果把 `rkey` 交给过远端，只检查本地 CQ 为空还不够。本地可能没有主动请求，远端却仍在读取或写入。双方需要停止授权对应的访问，并确认旧请求结束，再回收内存。

注销后重新分配或重新注册，即使地址数字相同，也不能继续使用旧的访问凭证。MR、地址与分配对象共同决定有效性。[连接与元数据](../04-optimization/04-connections-metadata.md)会进一步解释如何处理对端缓存的旧信息。

## 用一个 MR 提供多个缓冲区

注册涉及内核与设备资源管理，通常比改变一条请求的地址和长度昂贵。程序可以先注册一个 1 MiB 内存池，再把它分成 256 个 4 KiB 区域。

每次传输只填写所选区域的地址、长度和同一个 `lkey`。区域可以独立借出和归还，但每块仍要等相关请求完成，整个 MR 则要等所有区域停止使用后才能注销。这样把注册成本移出频繁收发的路径，也把内存池的管理责任交给应用。

MR cache 还必须跟踪底层分配的寿命。仅凭指针数值命中缓存，无法证明这个地址仍属于原来的对象。相关机制见 [3.3](../03-internals/03-memory-registration-dma-iommu.md#registration-cost)。

## 对照实验中的地址和 key

运行 `02_resource_lifecycle`，找到打印 MR 地址、长度和两个 key 的一行。再看它注册与注销之间没有传输请求，因此可以直接进行清理。

作为阅读练习，可以先预测：如果把注册长度缩小一半，但后续仍请求原长度，会在哪个层次检查出问题？错误可能在投递或执行阶段暴露，取决于具体检查位置，不能只等待某一个固定错误码。涉及错误访问的修改应在单独实验进程中进行。
